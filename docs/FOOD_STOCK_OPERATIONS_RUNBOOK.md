# #208 食品、订单与实物流转运行手册（尚未上线）

仅预包装食品和瓶装饮料；现制不自动扣配方。共享商品资料、门店独立售价。详细事务及权限设计见 `ADR_FOOD_ORDER_AND_PHYSICAL_FLOW.md`。

## 默认关闭与迁移范围

`FOOD_STOCK_WRITES_ENABLED=false`、`FOOD_CHECKOUT_ENABLED=false`。仅明确字符串 true 能开启；结算还要求库存开关同时开启。代码/测试不是现场启用授权。停止新订单后，对已有订单取消/已确认退款仍可安全释放原预留，绝不把释放当物理入库。

- 0042 多批次总账；0043 门店独立售价；0044 可空食品来源分类/新批次入库；0045 显式冻结/召回/过期销毁。
- 0046 原 FEFO 预留基础保留，不改历史。
- 0047 正式订单分配、SOLD/物理 SALE 对应、总和及身份约束；0048 独立实物退货、调拨溯源、祖先校验及退款原状态；0049 同原分配同接收凭证唯一。

本轮仅在专用临时 PostgreSQL 验证标准 0000–0049；未在共享、Staging、生产或 Mac 执行迁移。

## 现场前置与失败停止

1. 负责人确认精确目标身份、授权范围、备份及**实际可恢复副本**，核对 0000–0046 journal、SQL hash 和 schema。旧食品草稿 0041 与 main 正式 0041 不同；遇到已应用旧食品 0041、缺失/不同 hash 不准自动修历史。
2. 停掉旧食品/订单/退款/调拨写进程，安排停写窗口。记录未履约订单/分配、已完成销售、退款、在途调拨及数量/金额基线；批次总量、预留/分配、来源未知或 NULL、父子溯源不符即 STOP。单 SKU 工作集超过 500 或来源超过 32 层/成环也停止，不截断后通过。
3. 先在专属恢复副本通过仓库标准迁移程序执行 0047–0049，禁止跳校验、改旧 SQL、禁触发器、直接改账。新退货/调拨证据表应为空，0046 原分配保留；核对物理库存、订单金额、支付/退款账本基线不变。
4. 核验 journal/hash、实际约束/触发器/函数定义，而非只看表存在。重跑订单/取消/自提/配送、退款不返实物、实物接收冻结、调拨对账、故障回滚、并发最后库存及召回竞争。最新 SHA 审核、专属 UI/UAT 和目标资源授权齐全后，才能另行执行现场应用/启用。
5. 失败保留脱敏证据与快照，开关保持关闭。新数据出现 SALE/PHYSICAL_RETURN/TRANSFER 或新退款原状态后，不能直接退回不识别这些类型的旧程序。按验证过的整库恢复方案恢复；不删流水、不伪造状态、不改 migration journal。

## 运营流程

- 食品先建非图书草稿、本店零库存关联；首次分类要求 catalog.edit、无销售/租借/库存历史且仅关联该店。不自动猜测食品来源；NULL 分类不能启用。
- 录入种类、批号、实际生产/到期日、数量与内部凭证。新批次默认 HELD。检查后显式释放；到期/召回及不可用祖先阻止释放、分配和履约。跨店溯源锁在库存行之前取得，多 SKU 升序。
- 食品下单使用正式选店报价；FEFO 原分配随订单同事务提交。自提/配送只扣原批次，重新验证日期和状态。
- 未付取消、未履约确认退款只释放预留。已履约退款处理金额，不增加 on_hand；**退款按钮不是收实物按钮**。
- 真实收到实物后，在双后台读取原订单 SOLD 分配，填写实际数量和唯一内部接收凭证，显式接收为新 HELD 批次，保留原日期/来源。累计不得超过原售出数量。同请求重试保持原键/凭证，不能为了重试换凭证重复记实物。
- 调拨沿用提交、发出、实际到店再接收；操作者须有两个门店授权范围和 transfer 权限。源批次与目的批次及双侧流水相连；接收默认冻结，检查后另行释放。普通入库/调整不能代替食品调拨。
- DISPOSAL 仅处理冻结/召回或到期批次，保留原状态，生成配对负向流水，不能消耗 reserved 或显式 blocked 数量。普通报损仍拒绝冻结/过期批次，禁止先释放或改日期绕过。
- 门店资金操作使用专门 storeId 路由，需相应 read/refund/reconcile 权限、Staff 数据范围和唯一订单履约门店匹配；旧 GLOBAL 财务入口限制不变，无自动赋权。只读溯源不公开另一店库存/人员/订单个人数据。

## 普通商品独立运营

食品两个开关关闭时，东门 Excel 只读预检→已有审核/实盘→独立批准→受保护导入，南门普通商品草稿→首次本店建档→不可变流水可独立运行。美萍只迁图书和实盘库存，不能把每行默认 1 件当实盘。普通商品不要求食品批次，不能让食品上线门槛阻塞普通建档。

真实数据/照片、浏览器交互、WeChat 真机、实际配送/支付、资质、共享环境迁移及正式部署均未验收。本机统一验证见 `I208_LOCAL_CODEX_HANDOFF.md`，禁止复用 #111 Gate B 或真实库存环境。
