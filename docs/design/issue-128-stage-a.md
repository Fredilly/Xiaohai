## 3. 三套视觉方向

### A — 雾蓝绘本 / Misty Reading（推荐）

这不是换一套颜色，而是“编辑型阅读轨道”：首页用横向封面 Hero + 继续阅读章节带；胖竹全球用地图主卡 + 附近门店行；我的用身份卡 + 阅读进度 + 横向订单轨道。小海内容是一本正在展开的书，胖竹仍是清晰的业务工具。

- 优点：最贴合“小海童话 + 高品质独立书店 + 家长友好”；真实 CMS/封面有明确视觉位置。
- 风险：需要真实内容媒体质量稳定，且要避免装饰压过可读性。
- 原型构图：`homeA` 阅读轨道、`globalA` 地图/门店、`meA` 进度/订单轨道。

### B — 胖竹自然 / Pangzhu Field Notes

小海首页改成“杂志目录”：主推封面占据左侧/上方，栏目索引组织童书、门店、动画和 AI；胖竹全球改成纸张上的地图手册，区域索引、找书路线和门店 sheet 形成纵向阅读；我的改成带时间线的阅读护照，而不是头像加网格。

- 优点：业务识别强，适合搜索、区域、门店详情和加盟入口，同时有完整的线下探索叙事。
- 风险：纸张/索引隐喻需要约束信息密度，不能让真实操作入口变成装饰。
- 原型构图：`homeB` 杂志封面+目录、`globalB` 地图手册、`meB` 护照时间线。

### C — 纸上剧场 / Paper Theatre

以深墨蓝舞台、章节海报和 cue 时间线组织产品：首页是完整舞台海报 + 内容 reel；胖竹全球是城市路线图 + 门店票根；我的则是 backstage，订单、作品和服务按 cue 顺序进入。它将故事、动画和 AI 创作作为第一品牌表达，而不是普通功能卡片。

- 优点：差异最大，故事、动画、AI 创作的叙事感和状态感强。
- 风险：深色主题对电商结算、长表单和家长阅读负担较高；必须先做对比度和媒体资产治理。
- 原型构图：`homeC` 舞台海报/reel、`globalC` 城市路线票根、`meC` backstage cue。

原型现在让三套方向在构图、内容顺序、品牌隐喻和组件形态上都不同，而不只是换色。原始 A/B/C 保留供设计比较；产品方最终选定 **B 首页 + A 胖竹全球 + B 我的**，参见第 0 节。C 可作为后续内容/AI 业务的探索参考。

### 排版与尺寸

- 页面标题 40–44rpx、区块标题 30–32rpx、卡片标题 26–28rpx、正文 23–25rpx、辅助文字 19–22rpx。
- 行高正文 1.55–1.7；中文长标题最多两行，不能用 `nowrap` 隐藏关键信息。
- 8rpx 基础间距，常用 16/24/32rpx；圆角 16/24/32rpx，避免每层都套卡片。
- 触达区域至少 88×88rpx；图标仅作辅助，入口必须有文字语义。
- 适配 320–430px 窄屏和 430–600px 宽屏；底部内容预留 `env(safe-area-inset-bottom)`。

### 图片、图标与状态

- 图片优先级：API/CMS/BOS 真实媒体 > 明确匹配的本地资产 > 结构化空封面；不得用 Logo、无关图片替换故事/商品图。
- Hero 16:9 或 4:3；书封 112×150rpx；门店图/地图占据主要视觉面；所有远程图固定尺寸并有错误回退。
- 图标使用线性、单色、24–32rpx；不混用 Emoji 和随机图标包。
- 每个列表均定义 `loading → ready → empty/error → retry`；错误状态不显示 0、余额或虚构条目。
- 付费/锁定/AI 处理中状态必须有明确语义和费用边界，不能用“成功”色伪装处理中。

## 5. 三主页面结构

### Home

A：品牌/搜索 → 横向 CMS Hero 与示意封面 → 继续阅读章节带 → 商城、童话、AI 三个文字入口。B：主推封面 + 杂志目录。C：舞台海报 + 内容 reel。三者都保留真实 CMS 图片优先、媒体失败回退和诚实空态，但内容阅读路径不同。

### Pangzhu Global

A：搜索/区域 → 地图主卡 → 附近门店行；B：地图手册 → 区域索引 → 门店 sheet；C：城市路线 → 门店票根 → 服务菜单。所有方向都保留地图、真实门店信息、找书入口，并要求错误时地图/数量/列表同步为“暂不可用/数量未知”，空结果才显示 0 和“没有找到门店”。

### Me

A：身份卡 → 阅读进度 → 横向订单轨道 → 服务；B：阅读护照 → 订单/租借/服务时间线；C：backstage → 订单、作品、服务 cue。三者均删除未接入真实接口的收藏/优惠券/积分假统计；登录前不展示财务、订单或作品数据，未开放服务明确标注。

## 6. 其他页面分期

1. **Stage B / 三 Tab 落地**：Home、Global、Me；只改 WXML/WXSS/必要展示适配，保留路由、API、状态机；独立 PR，窄/宽屏 + loading/empty/error/retry 验收。
2. **Stage C / Commerce**：Shop、Product、Cart、Checkout、Orders、Order Detail、Address；先定义真实数据卡片和订单状态筛选视觉，支付/库存语义由现有 API 保持不变。
3. **Stage D / Content**：Stories、Story Detail、Playback、Picture Books、Picture Book Detail、Animations、Animation Detail；统一封面、章节、媒体错误和继续播放状态，依赖 #70/#113 证据。
4. **Stage E / AI**：Story Create/Works、Picture Book Create/Detail、Animation Create/Detail；统一 Job 状态、成本提示、失败/重试、审核和媒体占位，不开启真实付费 AI。
